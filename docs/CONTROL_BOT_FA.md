# راهنمای مالک — ربات کنترل تلگرام

این ربات یک **کنترل‌کننده** برای سرویس موجود است، نه مسیر جدید معامله. هر سیگنال
همچنان از پارسر، کنترل ریسک، اندازه‌گذاری، بررسی موجودی، ثبت intent و تطبیق عبور
می‌کند. ربات به‌تنهایی معامله را فعال نمی‌کند و هیچ‌گاه برداشت، فیوچرز یا حالت
خودکار را بدون تأیید صریح شما روشن نمی‌کند.

> پیش‌فرض امن: **تأیید انسانی**. حالت خودکار فقط پس از دو هشدار و تأیید صریح فعال
> می‌شود و با هر بار ری‌استارت سرویس به تأیید انسانی برمی‌گردد.

## ۱. پیش‌نیازها

- حساب تلگرام شخصی که عضو/خواننده کانال سیگنال است.
- یک ربات ساخته‌شده با `@BotFather` و توکن آن.
- شناسه عددی تلگرام شما (همان `CONTROL_OWNER_USER_ID`).
- کلید MEXC فقط با دسترسی **خواندن موجودی + معامله Spot**. کلید برداشت مجاز نیست.
- اجرای سرویس با `tg-ingest serve` روی همین سرور.

## ۲. تنظیم امن

در فایل خصوصی `.env` (هرگز commit یا در چت ارسال نشود):

```bash
CONTROL_BOT_TOKEN=توکن-ربات
CONTROL_OWNER_USER_ID=شناسه-عددی-شما
CONTROL_SECRET_KEY=یک-کلید-تصادفی-بلند
# اختیاری: وقتی توکن و شناسه تنظیم شده باشند، پیش‌فرض فعال است
# CONTROL_BOT_ENABLED=true
```

برای ساخت `CONTROL_SECRET_KEY` یک‌بار اجرا کنید و خروجی را فقط در `.env` نگه دارید:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

- اگر `CONTROL_SECRET_KEY` نباشد، ذخیره کلید MEXC انجام نمی‌شود و مرحله MEXC
  به‌صورت امن متوقف می‌ماند. کلید را گم نکنید؛ بدون آن باید کلیدهای MEXC را دوباره
  وارد کنید.
- توکن ربات و Secret MEXC هرگز در چت، لاگ یا خروجی وضعیت نمایش داده نمی‌شوند.
- فایل‌های `.env`، نشست تلگرام و دیتابیس نباید در گیت باشند.

بررسی آفلاین:

```bash
cd /opt/projects/akha1
tg-ingest control status
```

## ۳. اجرا

ربات کنترل **بخشی از `tg-ingest serve` نیست** و به‌صورت جداگانه اجرا می‌شود:

```bash
tg-ingest control run
```

`serve` فقط دریافت پیام‌ها، صف پردازش و موتور معاملات را اجرا می‌کند و از ربات
کنترل تنها کلاینت Bot API را برای اعلان‌های ماندگار استفاده می‌کند. خود ربات
(پردازش دستورها و منوها) فقط با `control run` بالا می‌آید.

- ربات فقط با `CONTROL_BOT_ENABLED` و پیکربندی کامل اجرا می‌شود.
- قفل `<db_path>.control.lock` مانع اجرای هم‌زمان دو نمونه از ربات است.
- ربات `manage run` برخلاف `control run` هم قفل serve و هم قفل control را
  می‌گیرد؛ بنابراین با `serve` هم‌زمان اجرا نمی‌شود.
- `control run` کار دریافت، بک‌فیل یا پردازش صف را انجام نمی‌دهد؛ برای این کار
  `serve` باید جداگانه در حال اجرا باشد.

## ۴. شروع و ادامه

در چت خصوصی ربات `/start` را بفرستید.

- وضعیت فعلی و مرحله بعدی نمایش داده می‌شود.
- `/start` هیچ‌چیز را بازنشانی نمی‌کند: نه نشست تلگرام، نه MEXC، نه کانال، نه
  پیشرفت یادگیری و نه حالت اجرا.
- فقط `CONTROL_OWNER_USER_ID` پاسخ می‌گیرد. دیگران پیش از دیدن یا تغییر وضعیت رد
  می‌شوند.
- اگر نشست تلگرام معتبر باشد ولی در دیتابیس ثبت نشده باشد، ربات ناسازگاری را نشان
  می‌دهد و برای **پذیرش صریح** دکمه می‌گذارد. هیچ نشستی خودکار جایگزین یا حذف نمی‌شود.

## ۵. ورود تلگرام (فقط ترمینال امن)

دکمه **راهنمای ورود امن (ترمینال)** را بزنید. ورود از چت ربات غیرفعال است؛
تلگرام کدهایی را که در چت تلگرام فرستاده شوند باطل می‌کند.

در یک ترمینال امن SSH روی همان سرور اجرا کنید:

```bash
cd /opt/projects/akha1
.venv/bin/tg-ingest auth login
```

1. شماره با کد کشور و `+` (مثال: `+15550101337`).
2. کد ورودی که تلگرام می‌فرستد.
3. رمز تأیید دو مرحله‌ای، فقط اگر فعال باشد.

نکات:

- شماره، کد و رمز فقط در همان ترمینال خوانده می‌شوند و در چت، دیتابیس، لاگ یا
  تاریخچه ذخیره نمی‌شوند. کد و رمز با ورودی مخفی خوانده می‌شوند.
- کد را در هیچ چت تلگرامی، حتی به ربات، نفرستید. `PHONE_CODE_EXPIRED` می‌تواند
  به معنای منقضی، استفاده‌شده یا باطل‌شده به دلیل اشتراک‌گذاری باشد.
- سرویس کنترل می‌تواند روشن بماند؛ قفل نشست از استفاده هم‌زمان جلوگیری می‌کند.
  اگر قفل مشغول بود، چند لحظه صبر کنید و دوباره تلاش کنید.
- `/cancel` عملیات جاری را لغو می‌کند و تنظیمات قبلی را حفظ می‌کند.
- برای قطع اتصال، از دکمه **قطع اتصال حساب تلگرام** و سپس تأیید دوم استفاده کنید.
  `/start` هرگز شما را خارج نمی‌کند.

## ۶. تنظیم MEXC

دکمه **تنظیم و تأیید MEXC** را بزنید:

1. API Key را بفرستید.
2. API Secret را بفرستید.
3. نتیجه بررسی حساب و دسترسی‌ها نمایش داده می‌شود.

قوانین:

- کلید باید فقط **Spot trade** و خواندن موجودی داشته باشد.
- کلید دارای دسترسی برداشت رد می‌شود.
- Secret پس از ذخیره دیگر نمایش داده نمی‌شود.
- برای تعویض کلید، دوباره از همین منو اقدام کنید. کلید جدید فقط پس از تأیید موفق
  جایگزین می‌شود.
- اگر بررسی شبکه/حساب ناموفق باشد، کلید ذخیره نمی‌شود و معامله فعال نمی‌ماند.

## ۷. انتخاب کانال

دکمه **انتخاب کانال سیگنال**:

- کانال‌ها صفحه‌بندی‌شده (حداکثر ۱۰ مورد در هر صفحه) نمایش داده می‌شوند.
- جستجو با بخشی از نام یا `@username` ممکن است.
- کانال انتخاب‌شده پیش از ذخیره دوباره اعتبارسنجی می‌شود.
- انتخاب کانال به‌تنهایی بک‌فیل یا معامله را فعال نمی‌کند.

## ۸. یادگیری قالب سیگنال

دکمه **ادامه یادگیری سیگنال**:

- برای هر پیام، متن اصلی و فیلدهای استخراج‌شده (نماد، جهت، ورود، اهداف، حد ضرر،
  حجم/مبلغ) نمایش داده می‌شود.
- **تأیید استخراج** فقط برای پیام‌های معتبر و قابل‌اقدام فعال است.
- **رد استخراج** یک نمونه معتبر، شمارنده نمونه‌های متوالی را صفر می‌کند.
- پنج نمونه معتبر متوالی تأییدشده، یادگیری را کامل می‌کند.
- پیام نامعتبر/مبهم قابل تأیید نیست و در شمارنده حساب نمی‌شود.
- تکمیل یادگیری مجوز معامله نیست؛ حالت پیش‌فرض همچنان تأیید انسانی است.
- **شروع دوباره یادگیری** با تأیید دوم انجام می‌شود و فقط نمونه‌های یادگیری را پاک
  می‌کند؛ کانال، تنظیمات و تاریخچه سفارش‌ها حفظ می‌شوند.

## ۹. اندازه سفارش

دکمه **اندازه سفارش**:

- **خرید:** مبلغ ثابت دلاری (پیش‌فرض `10`). یعنی برای هر سیگنال خرید، سقف مبلغ
  اسمی همان مقدار است، نه کل موجودی.
- **فروش:** درصدی از **موجودی آزاد** دارایی پایه (پیش‌فرض `25%`).
- در سرویس تولیدی `tg-ingest serve`، مبلغ ثابت `order_quote_amount` در
  `config.toml` مرجع است و هیچ مقدار پیش‌فرض نرم‌افزاری وجود ندارد. درصد سپرده
  سیگنال، درصد موجودی یا اهرم هرگز اندازه سفارش را تعیین نمی‌کند.
- هر دو حالت همچنان با ذخیره حداقل موجودی، بافر کارمزد، دقت قیمت/مقدار، حداقل
  ارزش سفارش و موجودی تازه بررسی می‌شوند. سقف سفارش‌های باز/روزانه، سن سیگنال و
  allowlist دستی در مسیر اجرا وجود ندارند.

## ۱۰. تأیید انسانی

در حالت پیش‌فرض، هر سفارش برنامه‌ریزی‌شده یک پیام تأیید می‌گیرد:

- دکمه‌های **تأیید سفارش** و **رد سفارش** یک‌بارمصرف هستند.
- هر دکمه به مالک، nonce، شناسه intent و نسخه همان سفارش گره خورده است.
- تأیید منقضی، nonce اشتباه، کلیک تکراری یا سفارشی که تغییر کرده، اجرا نمی‌شود.
- مهلت پیش‌فرض تأیید ۵ دقیقه است.
- تأیید فقط همان نسخه سفارش را اجرا می‌کند؛ نتیجه نامشخص هرگز دوباره ارسال نمی‌شود
  و به تطبیق سپرده می‌شود.

## ۱۱. حالت خودکار و توقف

- **حالت خودکار** فقط وقتی فعال می‌شود که تلگرام، MEXC، کانال و یادگیری کامل شده
  باشند. ابتدا هشدار نمایش داده می‌شود و سپس دکمه تأیید دوم لازم است.
- همه محدودیت‌های ریسک، اندازه، موجودی، سن سیگنال و تطبیق باقی می‌مانند.
- با `/pause` یا دکمه **توقف اجرای سفارش**، اجرای سفارش‌های جدید فوراً متوقف و حالت
  خودکار غیرفعال می‌شود.
- با `/resume` یا دکمه **ادامه اجرا**، اجرا در **حالت تأیید انسانی** ادامه می‌یابد.
- پس از ری‌استارت سرویس، حالت خودکار به تأیید انسانی برمی‌گردد و باید دوباره با دو
  مرحله تأیید شود. این رفتار عمدی است.
- ربات هیچ‌گاه حالت `live`، برداشت، فیوچرز یا allowlist خالی را فعال نمی‌کند.

## ۱۲. اگر تلگرام قطع باشد

ارسال پیام‌های تأیید و اعلان‌ها best-effort است. وضعیت واقعی سفارش در SQLite مرجع
است. در صورت قطعی تلگرام:

```bash
tg-ingest trading intents --limit 20
tg-ingest trading reconcile
tg-ingest control status
```

فرض نکنید سفارش ناموفق شده است. سفارش با وضعیت نامشخص عمداً دوباره ارسال نمی‌شود.

## ۱۳. عیب‌یابی سریع

| نشانه | کار |
| --- | --- |
| `control status` می‌گوید `MISSING CONTROL_SECRET_KEY` | کلید تصادفی را در `.env` بگذارید و سرویس را ری‌استارت کنید |
| ربات پاسخ نمی‌دهد | توکن، `CONTROL_BOT_ENABLED`، اتصال سرور و لاگ سرویس را بررسی کنید |
| `control refused to start` | نمونه دیگری از کنترل‌کننده در حال اجراست؛ اول آن را متوقف کنید |
| تلگرام `unreachable` است | پروکسی/شبکه را بررسی کنید؛ این وضعیت به معنی حذف نشست نیست |
| ورود می‌گوید نشست معتبر است | از دکمه پذیرش صریح استفاده کنید؛ ورود دوباره لازم نیست |
| MEXC رد می‌شود | دسترسی برداشت را بردارید و فقط read + Spot trade بگذارید |
| تأیید منقضی شده | سفارش اجرا نمی‌شود؛ برای سیگنال جدید منتظر تأیید تازه بمانید |

## ۱۴. حریم خصوصی و امنیت

- فقط مالک عددی مجاز است.
- پیام‌های حاوی شماره/کد/رمز در حافظه پردازش می‌شوند و در دیتابیس ذخیره نمی‌شوند.
- کلید MEXC رمزنگاری‌شده است؛ Secret خام در دیتابیس نیست.
- توکن ربات و Secret هرگز در وضعیت یا خطاهای چت چاپ نمی‌شوند.
- برای امنیت بیشتر: تأیید دو مرحله‌ای تلگرام، کلید MEXC با IP allowlist، و نگهداری
  خصوصی `.env` و `config/`.
